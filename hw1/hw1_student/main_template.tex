\begin{solution}
To analyze the time-complexity of this algorithm, we start with the outer loop. This iterates for all $n$ hospitals as they are matched one at a time, giving this operation
$\bigO(n)$ run time. Next, the inner loop defines the proposal of the given hospital to each doctor, of which there are also $n$. In the worst case, all $n$ doctors will be proposed to.
This gives the inner loop $\bigO(n)$ run time for a current overall time-complexity of $\bigO(n^2)$. Within this loop, there are a series of operations. The first operation is a $pop()$ from the beginning of the list. The time-complexity 
would be $\bigO(n)$ since the following elements have to shift after the removal. The Dict presence check, Set $add()$ and Set $remove()$ 
are all constant $\bigO(1)$ operations on average since they involve hashing. However, the $index()$ operation on a List is definitely a $\bigO(n)$ operation, since it requires a linear scan in the worst case.
\\This gives the implementation a total run time of $\bigO(n^3)$.
\end{solution}

\begin{solution}
In my $\bigO(n^2)$ implementation of the G-S algorithm, I kept the two $n$ sized 
Lists for doctor and hospital preferences. I also kept the Set of hospitals, but used it to contain the set of 
unmatched hospitals, as opposed to matched hospitals. This is so that I can use it to determine which hospital to 
process next almost like a queue, which "drives" the top loop of the algorithm. In p1\_b, the set is used to check 
if the current hospital being processed has already been matched. Lastly, I kept the Dict of doctors to hospitals.
\\\\
As optimization, I added a new data structure. The issue with the p1\_b was that the membership checking with $List.index()$
to find a doctor's preference was contributing linear time to the inner loop. Instead, we can do extra work before the 
loop starts to construct an $n$ by $n$ matrix of hospital rankings for each doctor. This allows constant time membership checking 
when evaluating the preference of a doctor.
\\\\
After adding this, I realized that the primary loop was still $\bigO(n^3)$ since each hospital could propose to each
doctor $n$ times in the worst case ($\bigO(n^2)$), and the determining the doctor to propose to takes linear time ($pop()$ 
from the hospital's preference list). To alleviate this, I implemented a data structure that tracks each hospital's preferred ranking, 
which would start from 0 (lowest ranking). Accessing the $i$th item in this List gives us hospital $i$'s preferred ranking in 
constant time. When their proposal gets rejected, we simply have to increment their preference ranking, which is also constant 
time. I keep the heuristic for a doctor's decision (keep or switch) the same as p1\_b, but it uses a matrix instead of a List 
as mentioned before.
\\\\
$\bigO(n^2)$ work is done upfront to create the data structures, then the main while loop is also $\bigO(n^2)$. 
The work within the while loop is all done in $\bigO(1)$ constant time.. Overall, the implementation maintains a $\bigO(n^2)$ 
run time.

\begin{solution}
The worst case for the G-S algorithm would involve maximizing the overall number of proposals. This would happen when every hospital experiences the maximum 
possible number of rejections. For this to occur, all the hospitals would need the same exact doctor preference order. This would result in all $n$ hospitals proposing 
to the same student, and $n-1$ get rejected. The next $n-1$ unmatched hospitals will go to the same next student, and $n-2$ will get rejected. In each round of proposals, 
the maximum number of rejections are being experienced. The order of the rejections will vary based on the student preference, but the number of rejections in a given round 
will always be equal to the number of currently unmatched hospitals minus one.
\end{solution}

\begin{problem}
In the {\em interval covering problem},
one is given a time interval $[0,M]$
and a collection of closed subintervals
$\mathcal{I} = \{[a_i,b_i] \mid i=1,2,\ldots,n\}$
whose union is $[0,M]$. (Interpret intervals as jobs
and, interpret $a_i$ and $b_i$ as the {\em start time}
and {\em finish time} of job $[a_i,b_i]$.)
The goal is to find a subcollection
$\mathcal{J} \subseteq \mathcal{I}$, containing
as few intervals as possible, such that
the union of the intervals in $\mathcal{J}$
is still equal to $[0,M]$.

You can assume that the
numbers $M,a_1,a_2,\ldots,a_n,b_1,b_2,\ldots,b_n$
are all non-negative integers, and that
$a_i < b_i$ for all $i$. You should assume
that the list of intervals given in the
problem input could be arbitrarily ordered;
in other words, don't make an assumption that
the input to the algorithm presents the intervals
sorted according to any particular criterion.

(\textit{20 points}) Below we have listed four greedy algorithms for
this problem. At least one of them is correct,
and at least one is incorrect. For {\em every} incorrect
algorithm, provide an example of an input instance
such that the algorithm outputs an incorrect answer
in your write-up.
(Either a set of intervals that fails to cover $[0,M]$,
or a set that covers $[0,M]$ but has a greater number
of intervals than necessary.) For {\em every} correct
algorithm, write, ``The algorithm is correct.''
For {\em at least one} of the correct algorithms,
implement the algorithm to run in $O(n \log n)$; that is 
$\Theta(n \log n)$ or faster.
In the write-up, indicate which algorithm you implemented
and briefly describe your implementation strategy. Include your implementation in \texttt{problem\_2/p2.py}.

  \begin{subproblem}
    \textbf{Select Earliest START Time:}
  Initialize $\mathcal{J}=\emptyset$.
  Until the intervals in $\mathcal{J}$ cover all of $[0,M]$,
  repeat the following loop: find the minimum $c \in [0,M]$
  such that $[c,M]$ is not yet covered by the intervals in $\mathcal{J}$,
  or if there is no such $c$ then set $c=M$; of all the intervals
  containing $c$ select one whose start time is as early as 
  possible and insert it into $\mathcal{J}$.
  \end{subproblem}

\begin{solution}
This algorithm is \textbf{not correct}\\\\
Counter-example:\\
Let interval = $[0,5]$\\
Let $\mathcal{I} = [[0,3], [1,4], [2,5]]$\\
$|\mathcal{J}| = 2$\\\\
This algorithm will start by correctly selecting $[0,3]$ as the first interval, 
since it hasn't selected an interval that covers $[0,5]$. Next, it will greedily
select $[1,4]$ because its start time is the next earliest and $[1,5]$ is not yet covered. 
Lastly, it will select $[2,5]$ since it has the next earliest start time and 
$[2,5]$ is not yet covered. This completely covers the entire interval $[0,5]$
for a total of 3 sub-intervals. However, there is actually a set of 2 optimal sub-intervals 
that covers $[0,5]$, $[[0,3], [2,5]]$.
\end{solution}

  \begin{subproblem}
    \textbf{Select Interval Maximizing Overlap Coverage::}
  Initialize $\mathcal{J}=\emptyset$.
  Until the intervals in $\mathcal{J}$ cover all of $[0,M]$,
  repeat the following loop: among all the intervals in
  $\mathcal{I}$ that are not already contained in the union
  of the intervals in $\mathcal{J}$, select one that is as
  long as possible (i.e., that maximizes $b_i-a_i$) and
  add it to $\mathcal{J}$.
  \end{subproblem}

\begin{solution}
This algorithm is \textbf{not correct}\\\\
Counter-example:\\
Let interval = $[0,6]$\\
Let $\mathcal{I} = [[0,3], [1,5], [3,6]]$\\
$|\mathcal{J}| = 2$\\\\
This algorithm will start by correctly selecting $[1,5]$ as the first interval, 
since it is the longest interval (4). Next, it has the choice between $[0,3]$ and 
$[3,6]$, which are both of length 3.\\
If it picks $[0,3]$ as the second interval, it will need an interval to cover $[5,6]$, 
so it will pick $[3,6]$ for a total of 3 subintervals.\\
If it picks $[3,6]$ as the second interval, it will need an intevral to cover $[0,1]$, 
so it will pick $[0,3]$ for a total of 3 subintervals.\\
In either case, it will choose 3 sub-intervals. However, there is actually a set of 
2 optimal sub-intervals that covers $[0,6]$, $[[0,3],[3,6]]$.
\end{solution}

  \begin{subproblem}
    \textbf{Delete Earliest Redundant Interval:}
    Initialize $\mathcal{J}=\mathcal{I}$. While there
  exists a redundant interval in $\mathcal{J}$ one
  that is contained in the union of the other intervals
  in $\mathcal{J}$ --- Identify the redundant interval that finishes first --- Remove this interval from $\mathcal{J}$.
\end{subproblem}

\begin{solution}
This algorithm is \textbf{correct}\\\\
Reasoning:\\\\
In a given step of the algorithm, we want to reduce the total number of sub-intervals, while still having a complete 
covering of the entire interval. For example, in the set $\mathcal{I} = [[0,1], [1,2], [0,2]]$, all sub-intervals are redundant, so it
is obvious that we don't have a minimal solution, i.e. the smallest number of sub-intervals needed to cover the interval. 
In this case, removing any sub-interval like $[0,1]$ reduces the total number of sub-intervals, while still maintaining a correct subset 
(though not the minimal subset).\\
To truly give us a minimal solution, we need a heuristic for "which" sub-interval to remove at a given step of the algorithm. If we think about 
the problem in terms of "choosing" the sub-intervals, we would want to pick intervals that have later finish times, so we can reach the goal 
of the covering the entire interval. Let's say there are two sub-intervals to pick from that are redundant. We will need to greedily pick one to
minimize the overall set, so it would be best to pick the one with the later finish time. Picking the earlier time potentially "leaves room" for more 
sub-intervals to be selected, which is not what we want. Choosing the later finish times is equivalent to removing the earlier finish times for 
this problem.\\\\
Implementation write-up:\\\\
In my implementation, my approach involves scanning the sub-intervals in groups, so that I can identify and remove redundant ones. To facilitate this 
I started by sorting the sub-intervals by their start time. This puts any potentially redundant sub-intervals next to each other. This operation is 
$\bigO(nlogn)$ right off the bat. Next, I went with a tumbling-window approach, where I evaluate sub-intervals with the same start time, because these 
sub-intervals are guaranteed to be redundant, i.e. only one of them needs to exist to cover a given range. Since I sorted earlier, I can do this through 
a linear scan. For a given start time, let's say $0$, I evaluate all the sub-intervals that have a start time of $0$, and keep track of the one with the 
latest end time. This is because we want to minimize the final set by removing the earliest end times, which is equivalent to including the 
latest end times. For example, I will scan $[[0,1], [0,3], [0,2]]$ and find that $[0,3]$ has the latest end time. Now, if I encounter a 4th sub-interval 
in the list that doesn't have a start-time of $0$, there are two cases:\\\\
A: The 4th sub-interval has the same finish time as the last one: $[[0,1], [0,3], [0,2], [1,2]]$\\
B: The 4th sub-interval has a different finish time as the last one: $[[0,1], [0,3], [0,2], [1,3]]$\\\\
In case A, $[1,2]$ is redundant, so I wouldn't even have to consider it.
In case B, $[1,3]$ could be considered because it covers the range $[2,3]$.
In either case, I know that $[0,3]$ is the best candidate of all sub-intervals with the start time $0$, so I can safely include it in the set 
of all sub-intervals that make up the minimum interval covering. The next iteration of the algorithm would evaluate all sub-intervals that have a 
start-time of $1$. In case A, it would discover that $[1,2]$ is redundant, and not include it in the final set. In case B, it would be compared to 
all other sub-intervals that also have a start time of $1$. This algorithm would have a top-level loop where the stopping condition is when the "current 
start time to evaluate" reaches $M$. That top-level loop is a function of $M$, and the primary work described earlier would sit within this loop, doing 
linear work (at most $N$ iterations where $N$ is the number of sub-intervals). This makes this part of the algorithm $\bigO(n)$.\\\\
Overall, the total work would be $\bigO(nlogn)$ (sorting) + $\bigO(n)$ (linear scan) = $\bigO(nlogn)$.
\end{solution}

{\bf A note about tie-breaking:}
When implementing any of the algorithms above one must
choose a tie-breaking rule. In other words, when more than
one interval meets the criterion defined in the algorithm
specification (such as the latest finishing redundant
interval) one must specify which of the eligible
intervals is chosen. In the context of this problem,
if you are asserting that an algorithm is correct,
it should mean that you believe the algorithm gives
the correct answer on every input instance
{\em no matter how the tie-breaking rule is implemented;}
that is what your proof of correctness should show.
When you assert an algorithm is incorrect,
for full credit you should supply an input instance
that leads to an incorrect output {\em no matter how
the tie-breaking rule is implemented.} However,
significant partial credit will be awarded for
